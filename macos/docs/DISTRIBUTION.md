# Mac 应用包与签名

当前交付 `FM Tactics Lab 0.8.0.app`，面向 Apple Silicon、macOS 14+。直接打开应用即可，不需要安装 Python、Homebrew、命令行工具或额外运行库，也不需要管理员安装步骤。存档读取组件已放在应用包内；FM 游戏仍需用户自行安装。

应用把数据写到当前用户的 `~/Library/Application Support/FM Tactics Lab Mac/`，不要求关闭 SIP，也不要求授予“完全磁盘访问权限”。读取受保护目录或外置磁盘时，macOS 仍可能显示正常的文件访问提示；这与安装权限不同。

## 没有 Apple 开发者账号时

本版使用本机临时签名（ad hoc），没有 Developer ID，也没有完成苹果公证。在本机构建的应用可直接运行，但通过网络下载、带隔离标记的副本可能被 Gatekeeper 拦截，**不能保证所有 Mac 下载后都无提示打开**。临时签名仅用于校验包内代码完整性，不是苹果对开发者身份的认证。

如果以后要向其他玩家分发默认可验证的下载包，需要 Apple Developer Program 中的 Developer ID 签名和公证流程。苹果说明见 [Developer ID](https://developer.apple.com/developer-id/) 与 [macOS 软件公证](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution)。届时还需重新验证加载本机 FM 插件及内置读取组件，不能只对现有 ZIP 换个签名标签。

## 网盘下载与首次打开

百度网盘等渠道请上传完整 ZIP，不上传拆开的 `.app`，也不要在线解压后重打包。应用外可以放说明，应用包内部不能加网盘广告、说明或其他文件。下载后在 Mac 本地完整解压，避免覆盖到旧版应用上。

“无法验证开发者”可能由未公证签名与下载隔离标记触发，不能据此认定网盘注入了内容。ZIP 只能固定上传时的内容，无法约束第三方服务；下载后的 SHA-256 与 GitHub 独立发布的值一致，才能确认压缩包没有变化。包内的 [`运行说明.txt`](../运行说明.txt) 给出了拖文件到终端校验、签名检查和逐类错误处理步骤。

- ZIP 校验不一致或解压报错：重新下载完整文件，不运行损坏副本。
- 校验通过、来源可信，但开发者无法验证：尝试打开后，到“系统设置 → 隐私与安全性 → 仍要打开”，只放行这一款应用。
- 提示“已损坏”：先重新完整解压，再运行 `codesign --verify --deep --strict` 检查该 `.app`；签名失败时联系发布者，不用批量清理隔离标记或关闭系统保护来掩盖问题。
- 系统明确报告恶意软件时，不按普通开发者提示绕过。

上述处理不能保证免系统确认；当前没有 Developer ID 或公证。苹果官方步骤见[在 Mac 上安全地打开 App](https://support.apple.com/zh-cn/102445)。

## 构建与发布校验

`bash macos/scripts/build.sh` 构建原生界面、两个引擎辅助进程和独立存档读取组件，再进行本机签名。构建需要 Command Line Tools 和 Python 3.11+；这些要求只针对开发者。

交付前检查深层签名、动态库依赖、移出仓库后的启动和存档读取。ZIP 使用 `ditto` 保留应用包结构与符号链接，从独立暂存目录只收录签名应用和 `运行说明.txt`。不加入 Finder 扩展属性、资源分叉或 `__MACOSX`；压缩后重新解压并验证深层签名。校验值在 `releases/macos-v0.8.0-SHA256.txt` 随提交和版本标签发布，用来发现传输变化，不代替 Developer ID 身份认证。包内不含 FM 引擎、游戏资源、用户存档或开发测试数据。

`dist/` 只保留当前版本。更新前退出旧应用；用户方案和历史实验保存在独立数据目录，清理旧应用不会删除它们。新格式方案不要交给旧应用编辑。

0.8.0 ZIP 共 150 个条目，已检查 CRC、标准 UTF-8 中文文件名、重复条目和内容范围。解压后的应用文件、执行权限、符号链接与构建包一致，深层签名通过。应用移到仓库之外后成功导入新存档的 24 队、502 人和 552 场赛程；原版宿主同种子运行的输入、比分、进度、事件与球队／球员统计一致。DAT 单队和 20 队导入也已通过正式包验证。这些是本机验证，不是苹果公证或其他 Mac 的实测结论。
