# 数据文件与实验记录

## 编辑中的球队和已经运行的实验

普通对战保存主队和对手。联赛保存自己的球队列表，每支球队包含球员、首发、战术、定位球和开赛状态。点击“复制普通对战主队／对手”会新建一支联赛球队，之后两边各自编辑。

联赛列表中的“阵容与属性”和“战术与定位球”打开同一支球队。顶部球队选择贯穿两个页面，修改自动写回该队。球队名称与战术名称分开保存；单队随机只重抽属性、隐藏数据与性格，保留名单和战术。

开始实验时，程序复制一份配置到实验目录，连同随机种子一起保存。后续编辑不会改变已运行的结果；停止后继续也使用这份配置。要测试新设置，应开始新实验。

每场报告保留实际加载的引擎 SHA-256；联赛 `run.json` 另存 `engineSHA256`，续跑时核对当前安装。旧实验没有这个字段时，从已有比赛确定版本。游戏更新后应新建实验，不能把不同引擎版本的比赛混入同一批次或联赛。

## 本机保存位置

`~/Library/Application Support/FM Tactics Lab Mac/`

| 文件或目录 | 内容 |
| --- | --- |
| `team-presets/<方案 ID>.json` | 命名球队方案，格式 `tactics-lab-mac/team-preset/1`；独立快照，不带对手和实验结果 |
| `team-presets/archived/` | 归档方案的原文件，可通过方案库重新导入 |
| `tactic-files/<操作 ID>/` | FMF 源文件、原版序列化数据、回读日志与核验结果 |
| `workspace.json` | 普通对战的主队、对手、战术及对照方案 |
| `simulation-workers.json` | 上次选择的并行通道数，范围 1–256 |
| `league-setup.json` | 当前联赛球队、规则和赛程 |
| `editing-league-team.json` | 当前编辑的联赛球队 ID，重开应用可恢复 |
| `league-setup-backups/` | 导入另一套联赛前保存的原配置，可用初始化 JSON 入口恢复 |
| `engine-runs/<批次 ID>/` | 普通测试的配置、批次信息、逐场结果与运行日志 |
| `league-runs/<实验 ID>/run.json` | 联赛开赛配置、赛程、种子、进度和结果 |
| `league-runs/<实验 ID>/matches/<序号>/` | 每场比赛的配置、原始日志和 `result.json` |
| `experiments/` | 历史统计批次；当前统计另存为 `experiment.json` |
| `original-matches.json`、`latest-batch.json`、`latest-league.json` | 最近查看的比赛和实验索引 |
| `save-imports/` | 从用户存档读取的球队目录与阵容 |

0.8 的 `TeamManagement.selection` 保存固定／随机／原版 AI，`tacticSeed` 保存随机战术种子；球员随机与战术随机各自独立。`LeagueSetup.defaultTactics` 是未覆盖对手的默认值，旧文件缺省仍为固定战术。`testTeamID` 记录待测球队；报告的 `reportTeamID` 只改变高亮，不修改冻结的设置。

AI 生成记录位于普通批次的 `tactics/` 或联赛的 `tactics/<赛程 ID>/`：`requested.json` 是请求，`generation.jsonl` 是原版回读，`resolved.json` 是实际比赛输入，`preparation.json` 绑定请求、回执和引擎指纹。批次 `preparation` 与联赛 `preparedTactics` 同时保存这些数据；续跑核对配置、种子、球员身份和引擎，不能拿新的编辑结果替换旧快照。AI 准备中停止也保留输入，已完成的生成结果不会重复生成。

`save-imports/` 也保存 DAT 目录和阵容输出。DAT 来源指纹由四个组件名称及各自文件 SHA-256 组合得到；读取选队时重新核对。输出球员的 `databaseRaw` 保留初始化前的值，`initializedFields` 记录补全数量；后续工作台保存的是已导入数值。数据库源文件不修改，也不复制进发布包。

逐场结果先写入，再更新汇总。并行比赛可能乱序完成，目录序号和种子仍对应固定对阵；恢复时扫描所有已完成场次，续跑只补缺失项，不假设结果连续。停止会取消当前批次拥有的子进程，已自然完赛且校验通过的结果仍保留。文件采用原子写入，未完赛比赛不计入统计。报告页的“打开保存位置”可找到整个联赛实验。

方案格式为 `tactics-lab-mac/5`，兼容读入 1–4，升级前留备份。新增可选 `matchStrategy`，保存三套方案、名称、当前编辑／开场方案、冷却间隔和规则。旧版指令草稿和定位球需核对后改用原版设置。新版文件不能交给旧版应用编辑。

原版比赛输入 `NativeScenario`：固定战术仍用版本 1，包含临场策略时使用版本 2。报告的 `analysisVersion` 独立于输入格式：1 包含终场进球和切换事件，2 另含切换时双方累计统计及终场控球时长。`goals` 和 `strategyEvents` 缺失表示旧报告未记录，不能视为没有事件。JSON 保留全部明细；CSV 保留逐场球队／球员统计，HTML 展示图表与事件。

方案库每次“保存为新方案”新建一份文件；载入只替换当前球队，导入文件总是加入新副本。修改工作台不会反向更新已保存方案。损坏文件保留并提示，不会用空数据覆盖。

## 导出怎么选

- 在游戏里载入战术：工作台导出当前编辑方案的 FMF，只包含双阶段阵型、角色、职责、心态及指令。球员属性、定位球、三套方案和切换规则另存完整球队 JSON。
- 复用完整单队：阵容方案库 JSON；普通对战的完整方案 JSON 包含双方，两种格式使用各自入口。
- 给人看结果：HTML 报告，包含图表、成绩与实际使用的球队配置。
- 继续分析：球队／球员 CSV；保存完整实验用 JSON。
- 复用球队和规则：联赛初始化 JSON；这份文件没有比赛结果。

导出的联赛结果 JSON 包含全部比赛、原始统计和配置，供外部分析或继续开发使用。目前应用恢复实验使用本机实验目录，尚无结果 JSON 的联赛恢复导入按钮。

## 数据格式与统计范围

球员 CSV 保留必需列 `name,position,pace,stamina,passing,decisions,tackling,finishing`，也支持对应中文表头。模板包含全部扩展属性列，可留空；已填写的属性必须为 1–20。`preferred_foot` 可填左脚、右脚、双脚或留空。名单 11–100 人，前 11 人成为初始首发；导入替换名单、保留站位并清除旧对照及定位球人员绑定，可撤销。

实验 CSV 支持上游原始列：`模式,方案,种子,主队进球,客队进球,耗时秒,尝试次数,日志`。此格式按主队视角计算，缺少对手和主客场，因此只能将**同一个固定条件批次**作为一个文件导入，不能混入不同阵容或比赛背景。

也支持扩展列：`variant,seed,goals_for,goals_against,opponent,venue,status,xg_for,xg_against`。前四列必需；`venue` 为 `home` 或 `away`；`goals_for` 始终指被测试球队进球，与其主客场无关。`status` 默认为 `complete`；失败、错误、取消和未完成行排除。重复的「方案 + 种子 + 对手 + 场地」拒绝导入。单文件最大 10 MB、20,000 行。

统计展示完整场次、胜率、场均进失球、场均积分；两方案按种子、对手、场地配对，比较净胜球差。不匹配的比赛只参与各方案描述汇总，不进入配对区间。至少 20 对样本才展示 1,000 次固定随机种子 bootstrap 的百分位 95% 区间；该阈值只是显示门槛，不保证样本足够。结果仅用于探索；多方案反复筛选后应在独立种子和对手上验证。xG 与其他可选统计只使用实际提供的值，未提供的数据不会生成。

样例 `samples/players.csv` 为虚构名单；`samples/demo-results.csv` 为人工测试数据，可验证导入界面，不可用于战术结论。

扩展球队指标：`possession`、`shots`、`shots_on_target`、`passes`、`completed_passes`、`crosses`、`completed_crosses`、`corners`、`fouls`、`offsides`、`tackles`、`interceptions`、`saves`、`yellow_cards`、`red_cards`，均以 `_for` / `_against` 区分本队和对手。控球率使用 0–100 百分数；成功传球／传中不能多于尝试次数、射正不能多于射门。`goals_for` 与 `goals_against` 必需，其余可留空。模板支持某一列，不等于原版适配器已经能读取该指标。

0.7 原版报告新增球队及球员 `crosses` / `completed_crosses`；JSON 还保存内部 `possession_ticks`，用于临场分段控球率，不作为 CSV 球队指标。每个切换事件的 `statistics` 是主、客队两个字典。完整战术分组、整场场均和分段每 90 分钟的计算见[统计口径](TACTICS_AND_AI.md#报告怎么看)。

球员赛后 CSV：先导入球队比赛，再导入球员文件。通过 `variant,seed,opponent,venue` 关联比赛；必填 `player_id,player_name,team`（`for` / `against`）。支持出场分钟、评分、进球、助攻、xG、xA、射门、射正、传球、成功传球、传中、成功传中、关键传球、创造机会、抢断、拦截、争顶、盘带、跑动公里、扑救、失球与红黄牌。程序可导出完整表头；没有对应比赛或同场球员重复时拒绝导入。不是 FM 原生导出格式，需要按模板整理。

## 默认输入值

未填写的属性用 10。自建球员默认年龄 25、身高 180 cm、体重 75 kg、CA 100、声望 5000；可在资料页修改。CA 不会反向分配属性。存档球员保留已解析的原始精度和资料。

标准开赛条件为体能／比赛状态 100%、疲劳 0、士气 20、凝聚力 80。自定义凝聚力可用 25–82，具体换算见 [引擎记录](MAC_ENGINE_STATUS.md)。这些默认值是为了控制实验条件。
