## 实际解决的 Mac 差异

- Mach-O 动态插件及其 `@loader_path/../Frameworks` 依赖，通过独立进程加载完整原文件。
- ICU 和模拟资源位于 **game_plugin.bundle 内部 Resources**。初始化原生文件系统和资源管理器，挂载 `simatch.fmf`、`simatchshared.fmf` 的虚拟目录后才能找到 xG 模型；只找到文件不够。
- arm64 C++ 间接返回结果使用 `x8`，需要 ABI 桥接；不能按 Windows 返回值约定调用文件／归档工厂。
- macOS TLV 描述符获取比赛线程上下文；不能复用 Windows TLS 槽。
- 对象大小、字段偏移和虚表布局不同。Mac match 大小为 `0x15590`；准备阶段种子位于 `+0x18`，不是 Windows 的 `+0x20`。比分访问使用 Mac 自身的结果对象虚表。
- 按原游戏性能测试路径构建派生比赛对象，调用原版反序列化、准备和运行方法。不修改机器指令，不伪造准备标志，不调用强制比分结束。
