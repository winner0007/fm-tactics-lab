## FMF 战术文件

对照 Windows 原项目，Mac 已接通原版战术写入、FMF 归档读取和战术解析；12 阵型逐项回读一致。中文名称、非默认个人指令、双阶段球员对应关系、角色职责和附加球队位保留。附加位／职责场景还通过原版赛前回读并自然完赛。畸形归档不能导入。证据见 `.build/evidence-v05/fmf/`。

战术文件不携带测试球员属性与定位球套路。这里验证的是本机原版归档和战术解析器，未声称已覆盖游戏 GUI 的所有导入场景或其他游戏版本。

## 输入核对

`EngineScenario.h` 在原版比赛准备前写入双方 11 名首发及最多 9 名候补的属性／资料，以及两阶段战术输入。原版准备后核对实际球员对象、规范战术、指令、主罚／角色优先级与队长，再运行比赛。读回不一致即失败，不能以加载成功代替比赛成功。

Mac 的 person key 返回位于 w0，采用 Itanium 虚表调用；不能照搬 Windows 间接返回。队长候选 key 与当前队长槽是不同字段。凝聚力准备公式会将团队影响与输入值混合，并限制相对输入的变化不超过 25；适配器反解此整数变换，双方共同可表达范围为 25–82，标准设为 80。没有绕过原版赛前运算。

角色、指令与定位球功能目录来自上游公开编辑器。221 个位置／角色个人指令策略在 Swift 和宿主之间同步；角色不适用、互斥指令、错误目标、残缺定位球任务与不支持资料范围在开赛前拒绝。完整配置和球员身份随报告持久化，读取历史时重新核对配置指纹、名单、赛程、种子顺序与统计合计。

可用的球队及球员统计仍限于下文已验证字段；没有把邻近内存字段猜作助攻或评分。联赛不延续跨场状态；未决规则保持并列。原始 .dat、定位球 FMF、战术磨合、关系效果和临场执教尚未映射。

每场两队各 20 条注册球员记录，包括未上场球员。原版统计中的射门、射正、传球、成功传球、xG 与球员合计逐项相符；牌数按原版球员记录汇总。种子 1：主队 8 射门 / 6 射正 / 510 传球 / 466 成功传球 / xG 0.814910；客队 11 / 5 / 617 / 574 / xG 1.399207。

原始证据位于忽略目录 `.build/evidence-v04/`，由 `scripts/check-engine.py` 可重新生成。`CheckEngineReports.swift` 校验真实报告与 CSV/JSON 转换，以及退出码、缺失终场、错误种子、错误二进制、伪装工作台输入、统计合计不一致等失败路径。

应用内另完成 5 场真实比赛，得到 200 条球员记录；校验重新读取结果一致且工作台未改动，渲染了引擎页、球队结果页、球员页三个真实数据视图。证据：`.build/evidence-v04/ui/ui-engine-validation.txt` 及同目录 PNG。

## 使用入口

打开 `dist/FM Tactics Lab 0.4.app`，在「引擎与接入」自动找到游戏后设置起始种子和场数，点击「开始原版模拟」。支持 1 / 5 / 10 / 20 场，逐场独立进程；可以停止，已完成场次保留。引擎页显示最近一场累计 xG，实验页显示本批次球队图表和球员基础统计。

球员姓名尚未映射，界面以原版 ID 标识。未确认的评分、助攻、出场分钟、跑动距离等保持缺失。每场日志、进度采样与完整报告存入应用数据目录；游戏包和存档不作修改。Mac 应用不携带游戏二进制、FMF 资源或 PKM 输入。

## 版本与输入约束

本机版本 `27.0.0.2493426`，插件包含 arm64 / x86_64；本次宿主仅支持 arm64。每次运行重新校验原始插件 SHA-256：

`774cacde63567fd3901c47719e7a6ed94cc3a0a62e9b94989dcac6b4890ec0e1`

输入为安装包的 `Contents/PlugIns/game_plugin.bundle/Contents/Resources/data/game_simulation/test match/match.pkm`（60,314 字节），SHA-256：

`39c594c7e876cc0ad325dfa51c377f4cf360840612479ed72d800ec548e504b6`

二进制或输入不匹配直接拒绝，不能仅凭版本字符串调用旧地址。Intel Mac、其他补丁版本、自选 PKM、游戏存档尚未接入。

## 实际解决的 Mac 差异

- Mach-O 动态插件及其 `@loader_path/../Frameworks` 依赖，通过独立进程加载完整原文件。
- ICU 和模拟资源位于 **game_plugin.bundle 内部 Resources**。初始化原生文件系统和资源管理器，挂载 `simatch.fmf`、`simatchshared.fmf` 的虚拟目录后才能找到 xG 模型；只找到文件不够。
- arm64 C++ 间接返回结果使用 `x8`，需要 ABI 桥接；不能按 Windows 返回值约定调用文件／归档工厂。
- macOS TLV 描述符获取比赛线程上下文；不能复用 Windows TLS 槽。
- 对象大小、字段偏移和虚表布局不同。Mac match 大小为 `0x15590`；准备阶段种子位于 `+0x18`，不是 Windows 的 `+0x20`。比分访问使用 Mac 自身的结果对象虚表。
- 按原游戏性能测试路径构建派生比赛对象，调用原版反序列化、准备和运行方法。不修改机器指令，不伪造准备标志，不调用强制比分结束。
